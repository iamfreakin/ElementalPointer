# 보스 기믹 시스템 — 언리얼 기술 설계

> 엔진: UE 5.8 / C++ 코어 + BP·DataAsset 데이터  
> 목표: 보스/기믹을 데이터로 계속 추가할 수 있는 확장형 구조  
> 작성일: 2026-06-01

---

## 0. 핵심 설계 결정

### GAS를 쓸 것인가? → **안 쓴다 (커스텀 컴포넌트)**

| 항목 | GAS | 커스텀 컴포넌트 (선택) |
|---|---|---|
| 셋업 비용 | 높음 (ASC, Attribute, Effect 보일러플레이트) | 낮음 |
| 학습 곡선 | 가파름 | 완만 |
| 이 게임 규모 적합성 | 오버킬 (보스 기믹은 상태머신 수준) | 적합 |
| 네트워크 | 강점 (싱글플레이라 불필요) | 무관 |

> 인크리멘탈 싱글플레이 게임이고, 기믹은 "페이즈 상태머신 + 타이머/조건 평가" 수준이라 GAS의 복잡도가 이득보다 크다. 단순한 커스텀 컴포넌트 + 데이터 에셋으로 충분하며 확장도 더 직관적이다.

---

## 1. 아키텍처 개요

```
ABossCharacter (보스 액터)
  ├─ UBossPhaseComponent      ← 페이즈 전환 상태머신
  ├─ UGimmickRunnerComponent  ← 활성 기믹 실행/평가
  └─ UDamageGateComponent     ← "딜 가능/무적" 게이트 관리

UGimmickBase (UObject, Instanced)   ← 기믹 1종 = 1 클래스
  ├─ UGimmick_WeakPoint        (약점 노출)
  ├─ UGimmick_SafeZone         (안전 구역)
  ├─ UGimmick_Channeling       (채널링 방해)
  └─ UGimmick_SequenceClick    (순서 클릭)

UBossDataAsset (DataAsset)          ← 보스 1종 = 1 에셋
  └─ Phases[] → 각 Phase에 Gimmicks[] (Instanced)

UCursorContext (커서 입력 추상화)    ← 위치/유지시간/클릭 제공
```

**확장 흐름**: 새 보스 = DataAsset 하나 추가. 새 기믹 = `UGimmickBase` 상속 클래스 하나 추가 → BP/DataAsset에서 인스턴스로 꽂음.

## 2. 커서 입력 추상화 — `UCursorContext`

기믹들이 커서 정보에 의존하므로, 입력을 한 곳으로 모은다. 기믹이 직접 PlayerController를 만지지 않게 한다.

```cpp
USTRUCT(BlueprintType)
struct FCursorState
{
    GENERATED_BODY()

    FVector WorldLocation;     // 커서의 월드 투영 위치 (전투 평면)
    FVector2D ScreenLocation;
    bool bPressedThisFrame = false;
    float HeldSeconds = 0.f;   // 특정 영역 내 연속 유지 시간 (기믹이 관리)
};
```

- 커서 → 월드 변환은 `DeprojectScreenPositionToWorld` 후 전투 평면(Z 고정)과 교차.
- 매 틱 갱신, 기믹은 읽기만 함.

## 3. 기믹 베이스 — `UGimmickBase`

모든 기믹의 공통 인터페이스. `Instanced` + `EditInlineNew`로 DataAsset에 인라인 편집 가능하게.

```cpp
UCLASS(Abstract, Blueprintable, EditInlineNew)
class UGimmickBase : public UObject
{
    GENERATED_BODY()
public:
    // 라이프사이클
    virtual void OnActivate(FGimmickContext& Ctx) {}   // 기믹 시작 (예고 연출 포함)
    virtual void OnTick(FGimmickContext& Ctx, float Dt) {}
    virtual void OnDeactivate(FGimmickContext& Ctx) {}

    // 평가 결과
    virtual EGimmickResult Evaluate(const FGimmickContext& Ctx) const
        { return EGimmickResult::InProgress; }

    UPROPERTY(EditAnywhere) float PreTelegraphTime = 1.0f; // 예고 시간
    UPROPERTY(EditAnywhere) float Duration = 5.0f;
};

UENUM()
enum class EGimmickResult : uint8 { InProgress, Success, Fail };
```

`FGimmickContext`: 보스 액터, 커서 상태, 페이즈 컴포넌트 참조를 묶은 경량 구조체 (기믹이 필요한 것만 접근).

## 4. 기믹 구현 예시

### 약점 노출 — `UGimmick_WeakPoint` (우선순위 1)

```cpp
UCLASS()
class UGimmick_WeakPoint : public UGimmickBase
{
    GENERATED_BODY()
public:
    UPROPERTY(EditAnywhere) FName WeakSocketName;   // 보스 메시 소켓
    UPROPERTY(EditAnywhere) float HitRadius = 80.f; // 커서 허용 반경

    virtual EGimmickResult Evaluate(const FGimmickContext& Ctx) const override;
    // 커서가 WeakSocket 반경 안 → DamageGate 열림(Success 유지), 밖 → 무적
};
```

- `OnActivate`: DamageGate를 **닫음**(무적). 약점 위젯/하이라이트 표시.
- `OnTick`: 커서가 약점 반경 내면 게이트 열고 딜 허용, 벗어나면 다시 닫음.

### 안전 구역 — `UGimmick_SafeZone` (우선순위 2)

- `OnActivate`: 위험 장판 데칼 표시 + `PreTelegraphTime` 후 발동.
- `Evaluate`: 발동 순간 커서가 장판 안 → Fail (공격력 N초 감소), 밖 → Success.

### 채널링 방해 — `UGimmick_Channeling` (우선순위 3)

- 보스가 힐/버프 채널링 시작.
- 커서를 채널링 포인트(머리 위 구슬)에 `RequiredHoldTime`만큼 유지 → 방해 성공.
- 실패 시 보스 체력 회복 or 버프 적용.

### 순서 클릭 — `UGimmick_SequenceClick` (우선순위 4)

- `TArray<FName> RuneOrder` — 정해진 순서대로 룬 클릭.
- 틀리면 진행 리셋, 제한시간 초과 시 보스 체력 일부 회복.

## 5. 페이즈 상태머신 — `UBossPhaseComponent`

```cpp
USTRUCT(BlueprintType)
struct FBossPhase
{
    GENERATED_BODY()
    UPROPERTY(EditAnywhere) float HealthThresholdPct = 1.0f;  // 이 체력% 이하 진입
    UPROPERTY(EditAnywhere, Instanced) TArray<UGimmickBase*> Gimmicks;
    UPROPERTY(EditAnywhere) float GimmickInterval = 8.0f;     // 기믹 발동 주기
};
```

- 보스 체력 변동 → `HealthThresholdPct` 기준으로 다음 페이즈 진입 판정.
- 페이즈 진입 시 `GimmickRunner`에 해당 페이즈 기믹 목록 전달.
- 페이즈 전환은 `OnPhaseChanged` 델리게이트로 브로드캐스트 (UI/연출 훅).

## 6. 딜 게이트 — `UDamageGateComponent`

기믹의 "딜 가능/무적" 상태를 한 곳에서 관리. 데미지 처리부가 이것만 보면 됨.

```cpp
bool bDamageAllowed = true;
// 약점 노출 기믹: 약점에 커서 있을 때만 true
// 채널링/순서 기믹 진행 중: false
```

> 원작의 "보스 무적 구간"을 이 컴포넌트로 일반화. 기믹 결과가 게이트를 여닫는 구조라 기믹↔데미지 로직이 분리됨.

---

## 7. 데이터 에셋 — `UBossDataAsset`

```cpp
UCLASS()
class UBossDataAsset : public UPrimaryDataAsset
{
    GENERATED_BODY()
public:
    UPROPERTY(EditAnywhere) TSoftClassPtr<ABossCharacter> BossClass;
    UPROPERTY(EditAnywhere) float MaxHealth;
    UPROPERTY(EditAnywhere) TArray<FBossPhase> Phases;
    UPROPERTY(EditAnywhere) float RaidTimeLimit = 15.f; // 원작 레이드 제한시간
};
```

- 새 보스 = 이 에셋 복제 후 값/기믹만 수정. **코드 수정 없음.**
- 기믹 조합·수치·페이즈는 전부 에디터에서 편집.

---

## 8. 실행 흐름 (런타임)

```
레이드 시작
 → BossDataAsset 로드 → ABossCharacter 스폰
 → PhaseComponent가 Phase[0] 활성화
 → GimmickRunner: GimmickInterval마다 기믹 Activate
     → PreTelegraph(예고) → Active → Evaluate → Success/Fail 처리
 → 보스 체력 임계치 도달 → 다음 Phase 전환
 → 체력 0 또는 제한시간 초과 → 레이드 종료(깨달음 지급 / 실패)
```

## 9. 구현 마일스톤

| 단계 | 작업 | 검증 |
|---|---|---|
| M1 | `UCursorContext` + 전투 평면 투영 | 커서 월드 위치 디버그 드로우 정확 |
| M2 | `UGimmickBase` + `DamageGateComponent` | 게이트 on/off로 데미지 차단 동작 |
| M3 | `UGimmick_WeakPoint` 구현 | 약점에 커서 올릴 때만 딜 들어감 |
| M4 | `UBossPhaseComponent` + DataAsset | 체력% 따라 페이즈 전환 확인 |
| M5 | SafeZone / Channeling 기믹 추가 | DataAsset만 수정해 보스에 장착 |
| M6 | 예고 연출(데칼·위젯) + 레이드 타이머 | 기믹 예고→발동 사이클 시각 확인 |
